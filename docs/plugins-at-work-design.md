# Plugins at work: optional, reviewed, off by default

**Status: design only, nothing built.** Card `plugins-optional-at-work`, base `main` at `ac12b33`. For Troy and the work security reviewer to approve, or change, before any code is written.

## What is asked

A way to share a plugin on a work machine without giving up the promise `selfcheck` proves today: **nothing is looked up, imported or run unless the owner named it, and a reviewer can check the exact bytes.**

## What exists today (checked in the code)

- Plugins are off at work: `profile work` exports `AGENTBOARD_LOCKDOWN=1` and `AGENTBOARD_NO_PLUGINS=1` (`profile.py:84-96`), and the gate refuses on either before it looks at `AGENTBOARD_PLUGINS` (`plugins.py:58-66`). A machine with a plugin installed still imports nothing (`plugins.py:145-147`, `doctor.py:130`). Run on a demo plugin: with the profile on and `AGENTBOARD_PLUGINS=1`, `agentboard plugins` says "locked: $AGENTBOARD_LOCKDOWN is set" and the plugin's command is refused.
- The work profile already runs two guards **inside the Python process**: every connection to anything but this machine is refused, and in `serve` no program may start (`guards.py`, `server.py:587`). Plugin code runs in that process, so they apply to it. Shown by a throwaway test: `urlopen("http://203.0.113.9/")` under the profile fails with "agentboard work profile: a connection to '203.0.113.9' is not allowed on this machine".
- The same test showed the limit: code that calls `profile._NET[0].uninstall()` switches the guard off. The guards are a net for mistakes, not a wall (`guards.py` says so itself).
- `selfcheck` already has a scanner that lists a Python file's imports, calls, dynamic code and URLs against tables (`selfcheck.py:44,55,73,118`) and refuses a package with dependencies (`selfcheck.py:271`).
- The page that a plugin's script joins allows only `'self'` for scripts, connections, images and fonts, and no forms (`server.py:83`). It does not stop a script from navigating the tab elsewhere.

## The proposal in one paragraph

The work profile keeps plugins **off**. The owner can add a **pin file**, `~/.config/agentboard/plugins-allowed` (next to the `profile` file; mode 0600), that names a plugin and the **hash of its installed files**. Under the profile, only a plugin with a pin whose hash matches, and whose code passes the same scan `selfcheck` runs on agentboard itself, is ever imported. Nothing else changes: no pin file, same code path and same `selfcheck` line as today.

## The rules

| Rule | Enforced by |
|---|---|
| Off unless pinned. No pin file, an unreadable one, or a line without a 64-hex hash: no plugin loads. | `plugins.load` reads the pin first; every error means "none" |
| A copied `config.toml` or `tasks.json` cannot turn a plugin on. The pin lives outside the project, like the `profile` file. | file location, as `profile.py` |
| A bare `AGENTBOARD_LOCKDOWN=1` (no profile) refuses every plugin, as today. `AGENTBOARD_NO_PLUGINS=1` set in a shell still wins. `AGENTBOARD_PLUGINS=1` is ignored under the profile. | `plugins.disabled_reason` |
| The installed files must hash to the pin **before** the plugin is imported. A mismatch imports nothing and shows as a FAIL. | `pluginreview.tree_hash` |
| No network or process module, no `eval`/`exec`/`pickle`, no computed import, no non-local URL, no third-party import, no `ctypes`. No import of `agentboard.guards`, `profile`, `lockdown` or `plugins` internals. | `selfcheck.scan_file` and its tables, run on the installed files |
| The package is a pure Python wheel: no `.so`/`.dylib`/`.pyd`, no `.pth` (it runs at every Python start), no scripts or data outside its folder, no dependencies. | `pluginreview` checks the file list and metadata |
| Surfaces: a command, route, state, source, doctor check or config section needs nothing more. A **page script** (`set_page`) or a **thread** (`add_thread`) is refused unless the pin names it. | `plugins.Api` raises, the plugin shows as failed |
| Outside connections and programs stay refused at run time for the plugin's code too. | `guards.py`, unchanged |

## How a reviewer inspects one

`agentboard plugins inspect <file.whl | name>` is read-only: it imports nothing and makes no call. It prints a report generated by agentboard (not written by the plugin author, so it cannot flatter itself): name and version, every file with its sha256, the **tree hash**, the entry point, dependencies (must be none), the scan result, and which `api.*` calls the code makes. The tree hash is a sha256 over the sorted `path sha256` lines of the installed files, leaving out `RECORD`, `INSTALLER`, `REQUESTED`, `direct_url.json` and `__pycache__`. It is computed from the bytes, from a wheel's zip entries or an installed folder alike, so the number from the wheel before install equals the number after.

The reviewer signs the tree hash. After install, `agentboard selfcheck` and `doctor` show per plugin: pinned, hash equal, scan clean, surfaces within the pin. A changed byte turns a PASS into a FAIL on the next run.

## Installing offline

1. Machine with network: build the wheel in a throwaway venv (the same step as `WORK-SETUP.md`). Carry the one `.whl`.
2. Work machine: `agentboard plugins inspect plugin.whl`. Reviewer reads it and approves the hash.
3. `pipx inject agentboard plugin.whl --pip-args="--no-index"` (venv route: `~/.agentboard-venv/bin/pip install --no-index plugin.whl`).
4. `agentboard plugins allow <name> --sha256 <hash>` (add `--surfaces page` only if the reviewer read the script). It checks the installed tree against the hash, asks you to type the name, and **refuses without a terminal** so an agent's shell cannot pin by accident. Then restart `agentboard serve`.
5. `agentboard selfcheck` and `agentboard doctor`. Undo: `agentboard plugins revoke <name>`, then uninstall the package.

Steps 1 and 3 were run with a demo plugin: `pipx inject … --pip-args="--no-index"` installs it, and the tree hash of the wheel equals the tree hash of the installed copy (same 5 files, same hash).

Order matters once: run `profile work` before installing a plugin. An installed plugin counts as a "home" signal for `agentboard init` (`cli.py:188`, `profile.home_signals`); with the demo plugin installed first, `init` wrote a board without the work profile line.

## What this does not give you

- **Not a sandbox.** Approved code runs in the board's process with its access. The scan finds the lazy and the accidental, the guards stop an honest mistake, and the review of the pinned bytes is the control. A determined author can write code a scan misses.
- **A page script is the widest surface.** The page policy stops it loading from or sending to another host, but not navigating the tab. So the pin names it separately and the reviewer reads the script, which is part of the hashed bytes.
- **Anything running as you can edit the pin file or the installed files.** Same limit as the `profile` file and the board's "no login" (`SECURITY.md`). The terminal rule on `allow` is a speed bump.
- **Home plugins stay home.** Texts and Facts ask `claude`, call an outside service or start a program, so they cannot pass the scan. That is the intended result.

## List of changes

1. `pluginreview.py` (new): `tree_hash`, the file-list and metadata checks, the report. Move the scan tables out of `selfcheck.py` into a small shared module so `plugins` need not import `selfcheck`.
2. `plugins.py`: read the pin, gate per plugin, hash and scan before `ep.load()`, `Api` refuses unpinned surfaces. Errors stay class names only.
3. `profile.py`: `apply()` sets `AGENTBOARD_NO_PLUGINS=1` exactly when no valid pin exists, so a machine without a pin runs today's path. `describe()` and its docstring say "only a pinned, hash-checked plugin".
4. `cli.py`: `agentboard plugins inspect | allow | revoke`; plain `agentboard plugins` also lists pinned ones.
5. `serverstate.py`, `doctor.py`, `selfcheck.py`: "plugins closed" becomes "closed, or only pinned and verified ones loaded"; new lines per pinned plugin; `selfcheck.py:481` and `:843` keep passing on a machine with no pin.
6. Tests: no pin means no import (a module that fails the test if imported); a bad or partial pin file means none; a changed byte is not imported; each banned import, `.pth`, native file and dependency is refused; an unpinned `set_page`/`add_thread` fails; a plugin's `urlopen` is refused under the profile; a bare lock still refuses; the pin file is the third home file in `test_signoff_files`.
7. Docs: `security-signoff.md` (new file row, the "plugin is trusted code" line, a new claim row), `SECURITY.md`, `WORK-SETUP.md`, `README.md`, the plugin section of `ARCHITECTURE.md`, `CHANGELOG.md`.
