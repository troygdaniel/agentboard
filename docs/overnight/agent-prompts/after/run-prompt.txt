## Before you claim: ask if anything's unclear

If this task is ambiguous, send your orchestrator/coordinating session (if you have one) one line
— e.g. via SendMessage — and wait for its answer before claiming: it sees the whole board and can often
answer without bothering the user. This is a one-time check, not a back-and-forth once work is underway.

## Step 0: claim this task (do this first)

Run this so the board knows you have it. Use your own session name:

    agentboard claim notes --name "<your session name>"

## Step 1: add subtasks as soon as you start

Every card has subtasks, always. Read the work, then add the steps right away: at least two, even on
a tiny card (do it, check it). Add more if you find more work as you go.

    agentboard add "<step>" --parent notes

## Progress reporting

The percentage is what the board/HUD show at a glance, so keep it honest: your real % of the work
done, not a fixed checklist. The card's % is the mean of its subtasks, so update the subtask you are on,
not the card. Call `update` whenever the estimate changes, including when you find more work than
expected (it can go down):

    agentboard update <subtask id> 50 "<what you are doing>"
    agentboard update <subtask id> 100 "<one-line result>"     # a subtask at 100% closes itself
    agentboard review notes "<one-line result>"

Finish with `review` — the user signs off and moves the card to done. This is an unattended one-shot run: after `review`, stop. The run ends when you do and nothing can wake you afterwards, so do not start a background wait.
NEVER mark your own task done: run `agentboard done notes` ONLY if the user explicitly tells you to.

If you are blocked on the user mid-task, flag it (and keep going once they answer):

    agentboard ask notes "<one-line question>"

The user answers on the card, not through anyone else. This is an unattended one-shot run: after `ask`, stop. The run ends when you do and nothing can wake you afterwards, so do not start a background wait.



## Working rules

- Take only the cards you are handed or have claimed by name. With an ORCH running, that is the cards it assigns: do not claim a card because it sits in Todo.
- This run already has a folder of its own: stay in it, edit nothing outside it, and never use `git stash` (every worktree shares one stash).
- A card with an unfinished blocker will not claim. Do not use `--force`: tell your orchestrator in one line, and take another card.
- Never put a backtick or `$(` inside a double-quoted command argument: the shell runs it. Use single quotes, or put long text in a file and pass `--body-file`.

These are not optional.
