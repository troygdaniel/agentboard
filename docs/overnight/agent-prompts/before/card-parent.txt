## Progress reporting

Each subtask has its own %, and this task's % is computed from them (the mean), so you do not set it.
Keep the subtasks honest, updated whenever your estimate changes (it can go down):

    agentboard update <subtask id> 50 "<what you are doing>"
    agentboard update <subtask id> 100 "<one-line result>"     # a subtask at 100% closes itself

`update refactor-billing 0 "<text>"` only sets this task's status line. When the whole deliverable is ready:

    agentboard review refactor-billing "<one-line result>"

Any subtask still open closes with it. The USER signs off and moves the card to done.
After `review`, do not sit idle: start `agentboard answer refactor-billing --wait --timeout 3600` as a background command (in
Claude Code, Bash with run_in_background) and end your turn. You are woken when the user replies, sends the card back,
closes it ("Done by the user"), moves it or removes it, and it prints what happened. A message the user sends you on the board
(your thread) wakes it too: answer with `agentboard chat send "<one line>" --name "<your session name>" --to the user`.
Between cards, stay reachable with `agentboard chat inbox --name "<your session name>" --wait 3600` in the background the same way.
Run `agentboard done refactor-billing` ONLY if the user explicitly tells you to.

If you are blocked on the user mid-task, flag it (and keep going once they answer):

    agentboard ask refactor-billing "<one-line question>"

The user answers on the card, not through anyone else. After you ask, do not sit idle: start
`agentboard answer refactor-billing --wait --timeout 3600` as a background command (in Claude Code, Bash with run_in_background)
and end your turn. You are woken when the user replies, and it prints their reply; then carry on. It also wakes when
the user sends you a message on the board (your thread, outside any card) and prints it: answer with
`agentboard chat send "<one line>" --name "<your session name>" --to the user`, then wait again. A tool that cannot
run background commands runs it in the foreground instead. If it times out with no reply, say you are still waiting.

Between cards, and any other time you would go quiet with nothing running, keep yourself reachable the same way:
`agentboard chat inbox --name "<your session name>" --wait 3600` as a background command. It prints the next line the user
sends you and exits, and that wakes you; nothing else does. The board shows who is listening, and a Stop hook reminds
a session that is about to go quiet without one.

These are not optional.
